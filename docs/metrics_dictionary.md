### Ключевые определения

| Термин | Определение | Событие-маркер |
|---|---|---|
| Активный пользователь | Отправил ≥1 сон за период. НЕ «зашёл на сайт». | dream_submitted |
| Активация | Первый отправленный сон | первый dream_submitted у пользователя |
| Новый пользователь | Впервые завершил регистрацию | registration_completed (бекенд) |
| Платящий | Совершил ≥1 успешную оплату | payment_succeeded (бекенд) |
| Первая оплата | Момент превращения в платящего | MIN(payment_succeeded) по пользователю |
| Период | день (DAU) / ISO-неделя (WAU) / месяц (MAU) | |

### Обозначения для формул
Считаем всё по бекендовым событиям (источник истины), по всем пользователям через COUNT(DISTINCT user_id):

| Обозначение | Что это | Как считать из событий |
|---|---|---|
| РЕГ (daily_metrics.registrations) | число регистраций | COUNT(DISTINCT user_id) где есть registration_completed |
| АКТ (daily_metrics.avtivated) | число активированных (отправили первый сон) | COUNT(DISTINCT user_id) где есть dream_submitted |
| ПЛАТ (paying) | число платящих | |
| ОПЛАТЫ (payment_counts) | число всех оплат (с повторными) | |
| ВИЗИТЫ (daily_metrics.visits) | число визитов/сессий | COUNT(*) строк session_started |
| VISITORS (daily_metrics.visitors) | число посетителей | COUNT(DISTINCT anon_id) строк session_started |
| СУММА (revenue) | выручка в ₽ | SUM(amount) из таблицы users_payment (сумма летит в properties события payment_succeeded) |
| РАСХОД | расход на рекламу | из кабинета Директ/VK 🟠 не событие — написать ETL скрипт который ходит в яндекс директ по апи и достает нужную инфу |

### AARRR: минимальный набор
CR = Conversion Rate (коэффициент конверсии) · CPL = Cost Per Lead (стоимость регистрации) · CAC = Customer Acquisition Cost (стоимость привлечения платящего) · ARPPU = Average Revenue Per Paying User (средняя выручка на платящего)

#### A — Acquisition (привлечение)

| Метрика | Формула из событий | Можно посчитать |
|---|---|---|
| CPL — стоимость регистрации | РАСХОД (по кампании) ÷ РЕГ (по кампании) | 🟠 нужен расход + UTM при регистрации |

#### A — Activation (активация)

| Метрика | Формула из событий | Можно посчитать |
|---|---|---|
| CR регистрация → первый сон | АКТ ÷ РЕГ | ✅ |

#### R — Retention (удержание)

| Метрика | Формула из событий | Можно посчитать |
|---|---|---|
| Возврат за 7 дней — отправил ещё сон кроме первого | COUNT(DISTINCT user_id) с ≥2 dream_submitted в окне [ registration_completed; +7 дней] ÷ РЕГ | ✅ |

> Определение: доля зарегистрированных, кто в первую неделю прислал не только первый сон, но и хотя бы ещё один — то есть продукт «зацепил».
Альтернатива: знаменатель АКТ вместо РЕГ — тогда это чистое удержание активированных (честнее отделяет удержание от активации). Выбери одно и зафиксируй.

#### R — Referral (рекомендации)
Пропускаем — нет события про приглашение друга. Появится механика → появится событие → посчитаем K-фактор.

#### R — Revenue (выручка)

| Метрика | Формула из событий | Можно посчитать |
|---|---|---|
| CR в первую оплату | ПЛАТ ÷ РЕГ | ✅ |
| CAC — стоимость платящего | РАСХОД ÷ ПЛАТ | 🟠 нужен расход + UTM при регистрации |
| ARPPU | СУММА ÷ ПЛАТ | ✅ |

> ⚠️ Главное сравнение: CPL vs CAC. Дешёвый по CPL канал часто дорогой по CAC — приводит регистрации, но не платящих.

### Дерево метрик (декомпозиция по формулам)
Каждый узел = произведение/отношение дочерних. Всё через события:
```
Выручка (СУММА)                                    ✅ SUM(amount) из users_payment
  = Число платящих (ПЛАТ) × ARPPU

  ├─ Число платящих (ПЛАТ)                          ✅
  │    = Регистрации (РЕГ) × CR в первую оплату
  │
  │      ├─ Регистрации (РЕГ)                        ✅
  │      │    = Визиты (ВИЗИТЫ) × CR визит→рег
  │      │
  │      │      ├─ Визиты (ВИЗИТЫ)                    ✅  = COUNT(session_started) по UTM
  │      │      └─ CR визит→рег                       ✅  = РЕГ ÷ ВИЗИТЫ
  │      │
  │      └─ CR в первую оплату                        ✅  = ПЛАТ ÷ РЕГ   ← здесь живёт ПЕРВАЯ оплата
  │
  └─ ARPPU                                            ✅
       = Средний чек × Частота оплат

         ├─ Средний чек        ✅  = СУММА ÷ ОПЛАТЫ
         └─ Частота оплат      ✅  = ОПЛАТЫ ÷ ПЛАТ   ← здесь живут ПОВТОРНЫЕ оплаты

```
